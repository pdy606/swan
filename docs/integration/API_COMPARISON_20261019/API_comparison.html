2. 기능 차이를 읽는 방법

이미지 입력과 영상·Live는 다르다

선택한 OpenAI·Claude 모델은 이미지와 텍스트를 받아 텍스트를 출력한다. Gemini 3.5 Flash-Lite와 3.8 Flash는 영상 입력도 지원하지만 해당 일반 모델은 Live API를 지원하지 않는다. 응답을 조금씩 받는 스트리밍이 카메라 영상을 실시간으로 주고받는 Live 기능과 같다는 뜻은 아니다. GPT-6 Luna 기능 · GPT-6.1 Sol 기능 · GPT-6 Astra 기능 · Claude Haiku 5.5 기능 · Claude Sonnet 5.5 기능 · Gemini 3.5 Flash-Lite 기능 · Gemini 3.8 Flash 기능

Robotics ER 2 일반 Preview는 구조화 JSON을 지원하고 Live는 미지원이다. Streaming Preview는 Live·함수 호출을 지원하지만 구조화 JSON은 미지원이다. Gemini Robotics ER 2 일반형·Streaming형

JSON 형식과 판단 정확도는 다르다

구조화 출력은 응답을 정한 형식으로 받는 기능이다. 잘못 본 신호를 올바른 JSON으로 답할 수도 있다. 현재 YOLO의 적색→초록 오인식이 새 API를 붙이면 해결된다고 판단하지 않는다.

Ollama는 로컬 이미지 입력과 JSON Schema를 지원한다. 공식 문서상 Ollama Cloud는 구조화 출력을 지원하지 않으므로 로컬과 클라우드를 같은 조건으로 쓰지 않는다. 로컬 Qwen 후보도 실제 이미지 응답과 형식 준수 여부는 별도 확인 대상이다. Ollama 이미지 입력 · Ollama 로컬 구조화 출력

4. 팀에 제안할 비교 순서

  1. 작은 비용으로 시작할 클라우드 후보: GPT-6 Luna와 Claude Haiku 5.5를 우선 비교 대상으로 제안한다. 가격과 이미지·JSON 지원을 기준으로 한 제안이며, 인식 정확도나 응답속도 순위는 아직 없다.
  2. 영상 입력을 검토할 때: Gemini 3.5 Flash-Lite와 3.8 Flash를 비교한다. 공간 추론 특화 기능은 Robotics ER 2 Preview를 추가 검토하되, 일반형과 Streaming형의 JSON·Live 차이를 유지한다.
  3. 외부 API 종량료를 줄일 때: 실행 자원이 맞으면 Qwen3.5 9B, 더 큰 자원을 쓸 수 있으면 최근 Qwen3.8 27B를 로컬 후보로 둔다. 무료 API료만으로 전체 비용·속도가 유리하다고 결론내리지는 않는다.
  4. 상위 비교 기준: Sol·Sonnet을 문서상 균형형 비교 대상으로, Astra는 고비용 참조 대상으로 남긴다. 먼저 작은 검증 자료에서 품질·지연 차이를 측정한 뒤 최종 선택한다.

위 순서는 조사에 근거한 제안이다. 지금 확정한 공급사·모델은 없으며, 실제 추가 성능 시험·연동 구현은 별도 작업이다.

5. 프로젝트에서 이미 확인한 범위

10/8 기록의 qwen3:8b는 LiDAR·오도메트리·목표 정보로 짧은 직선 주행을 시험했다. 당시 카메라 이미지를 AI 입력으로 사용하지 않았다. 필터 LiDAR 조건의 응답 중간값 0.840초는 그 시험의 기록이며 이번에 조사한 Qwen3.5·Qwen3.8 또는 클라우드 모델의 지연으로 사용하지 않는다. 당시 시험 기록

이번 비교는 10/1의 기존 API 메모를 최신 공식 기능·가격과 대조해 확장한 자료다. 신호 색상·사람·오토바이의 정답 자료를 이용한 모델별 정확도, 실제 응답 지연, JSON 실패율, 반복 성공률은 아직 측정하지 않았다. 특히 10/18 YOLO 점검의 신호 오인식과 이 API 기능 조사는 별개의 결과다.
